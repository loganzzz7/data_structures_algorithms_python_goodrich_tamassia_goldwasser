# 8.4 Tree Traversal Algorithms
A **traversal** of a tree `T` is a systematic way of accessing, or "visiting," all the positions of `T`. The specific action associated with the "visit" of a position `p` depends on the application of this traversal, and could involve anything from incrementing a counter to performing some complex computation for p.

## 8.4.1 Preorder and Postorder Traversals of General Trees
**Preorder Traversal**:
- The root of `T` is visited first and then the subtrees rooted at its children are traversed recursively. If the tree is ordered, then the subtrees are traversed according to the order of the children. 
    - Order: `root -> left -> right`
```python
Algorithm preorder(T, p):
    perform the "visit" action for position p
    for each child c in T.children(p) do:
        preorder(T, c)          # Recursively traverse the subtree rooted at c
```

**Postorder Traversal**:
- "Opposite" of the preorder traversal, it recursively traverses the subtrees rooted at the children of the root first, and then visits the root (hence, "postorder"!!)
    - Order: `left -> right -> root`
```python
Algorithm postorder(T, p):
    for each child c in T.children(p) do:
        postorder(T, c)         # Recursively traverse the subtree rooted at c
    perform the "visit" action for position p
```

**Running-Time Analysis**:
- Non-recursive part of the traversal algorithm takes time $O(c_p + 1)$ where $c_p$ is the num of children of $p$, under the assumption that the "visit" itself takes $O(1)$ time.
    - Overall running time for the traversal of tree `T` is $O(n)$, where $n$ is the num of positions in the tree. This running time is asymptotically optimal since the traversal must visit all the $n$ positions of the tree.

## 8.4.2 Breadth-First Tree Traversal--BFS
Visit all the positions at depth $d$ before visiting the positions at depth $d + 1$--**breadth-first traversal**
- This is a common approach used in software for playing games. A **game tree** represents the possible choices of moves that might be made by a player (or computer) during a game, with the root of the tree being the initial configuration for the game.
    - i.e. Tic-Tac-Toe
    - A breadth-first traversal of such a game tree is often performed because a computer may be unable to explore a complete game tree in a limited amount of time. So the computer will consider all moves, then responses to those moves, going as deep as computational time allows.
- Pseudo-code: 
    - Non-recursive, since we are not traversing entire subtrees at once. Use a queue to produce a FIFO semantics for the order in which we visit nodes. $O(n)$ tunning time due to $n$ calls to `enqueue` and $n$ calls to `dequeue`.
    ```python
    Algorithm breadthfirst(T):
        init queue Q to contain T.root()
        while Q not empty do:
            p = Q.dequeue()
            perform the "visit" action for position p
            for each child c in T.children(p) do:
                Q.enqueue(c)
    ```

# 8.4.3 Inorder Traversal of a Binary Tree
The standard preorder, postorder, and breadth-first traversals that were introduced for general trees, can be directly applied to binary trees.
- **Inorder Traversal**:
    - Visit a position between the recursive traversals of its left and right subtrees. The inorder traversal of a binary tree `T` can be viewed as visiting the nodes of `T` from "left to right". For every position `p`, the inorder traversal visits `p` after all the positions in the left subtree of `p` nd before all the positions in teh right subtree of `p`.
        - **ORDER**: `left -> root -> right`
    ```python
    # Pseudo-code for inorder traversal algo
    Algorithm inorder(p):
        if p has a left child lc then:
            inorder(lc)     # recursively left tree
        perform the "visit" action for position p
        if p has a right child rc then:
            inorder(rc)     # recursively right tree
    ```

**Binary Search Trees**:

An important application of the inorder traversal algorithm arises when we store an ordered sequence of elts in a binary tree, defining a structure we call a **binary search tree**. Let `S` be a set whose unique elts have an order relation. 
- i.e. `S` could be a set of integers. A binary search tree for `S` is a binary tree `T` s.t. for each position `p` of `T`:
    - Position `p` stores an elt of `S`, denoted as $e(p)$
    - Elts stored in the left subtree of `p` (if any) are less than $e(p)$
    - Elts stored in the right subtree of `p` (if any) are greater than $e(p)$
Use a binary search tree `T` for set `S` to find whether a given search value `v` is in `S`, by traversing a path down the tree `T`, starting at the root. At each internal position `p` encountered, compare our search value `v` with the elt $e(p)$ stored at `p`. 
- If $v < e(p)$, then the search continues in the left subtree of `p`.
- If $v = e(p)$, then the target is found and the search terminates
- If $v > e(p)$, then the search continues in the right subtree `p`.
    - Finally, if an empty subtree is reached, then the search terminates unsuccessfully.
- In other words, a binary search tree can be viewed as a binary decision tree, where the question asked at each internal node is whether the elt at that node is less than, or eq to, or greater than the elt being searched for.
    - The running time of searching in a bst `T` is proportional to the height of `T`--size ranging from $log(n + 1) - 1$ to $n - 1$

## 8.4.4 Implementing Tree Traversals in Python
When first defining the tree ADT in Section 8.1.2, we stated that tree `T` should include support for the following methods:
1. `T.positions()`: Generate an iteration of all positions of tree `T`
    - To implement the `positions` method, we have a choice of tree traversal algo. Given there exists advantages to each of those traversal orders, independent implementations of each strat should be called directly by a user of the class
2. `iter(T)`: Generate an iteration of all elts stored within tree `T`
    - The `iter(T)` method can be provided by a concrete implementation of the special method `__iter__` within the abstract base class `Tree`--rely on python's generator syntax:
        ```python
        def __iter__(self):
            """Generate an iteration of the tree's elts"""
            for p in self.positions():
                yield p.element()
        ```

**Preorder Traversal**:

Support a public method with calling signature `T.preorder()` for tree `T`, which generates a preorder iteration of all pos within the tree. The recursive algo for generating a preorder traversal must be parameterized by a specific position within the tree that serves as the root of a subtree to traverse -> soln: define a nonpublic utility method with the desired recursive param, and then to have the public method `preorder` invoke the nonpublic method upon the root of the tree. 
- Code implementations:
    ```python
    def preorder(self):
        """generate a preorder iter of pos in the tree"""
        if not self.is_empty():
            for p in self._subtree_preorder(self.root()): # start recursion
                yield p
    
    def _subtree_preorder(self, p):
        """generate a preorder iter of pos in the subtree rooted at p"""
        yield p                                         # visit p before subtrees

        for c in self.children(p):                      # for each child c
            for other in self._subtree_preorder(c):     # do preorder of c's subtree
                yield other                             # yield each to caller
    ```
- Both `preorder()` and `_subtree_preorder()` are generators. Rather than performing a "visit" action from within the code, yield each pos to the caller and let the caller decide what action to perform at the pos.

**Postorder Traversal**:

Code implementation:
```python
def postorder(self):
    """Generate a postorder iter of pos in the tree"""
    if not self.is_empty():
        for p in self._subtree_postorder(self.root()):
            yield p
        
def _subtree_postorder(self, p):
    """Generate a post order iter of pos in subtree rooted at p"""
    for c in self.children(p):
        for other in self._subtree_postorder(c):
            yield other
    yield p
```

**Other Traversals**:

```python
def breadthfirst(self):
    """Generate a breadth-first iter of the pos of the tree"""
    if not self.is_empty():
        fringe = LinkedQueue()
        fringe.enqueue(self.root())         # add root to queue at start

        while not fringe.is_empty():        # while queue
            p = fringe.dequeue()            # curr = front of queue
            yield p                         # report pos
            for c in self.children(p):      # then add children to back of queue
                fringe.enqueue(c)

def inorder(self):
    """Generate an inorder iter of pos in the tree"""
    if not self.is_empty():
        for p in self._subtree_inorder(self.root()):
            yield p

def _subtree_inorder(self, p):
    """Generate an inorder iter of pos in subtree rooted at p"""
    # left first
    if self.left(p) is not None:
        for other in self._subtree_inorder(self.left(p)):
            yield other
    
    # itself
    yield p

    # right nxt
    if self.right(p) is not None:
        for other in self._subtree_inorder(self.right(p)):
            yield other
```
