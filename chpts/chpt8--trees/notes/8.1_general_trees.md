# 8.1 General Trees
Non-linear data structure: `trees`
- Allows for the implementation of a bunch of algorithms faster than when using linear data structures (i.e. array-based lists or linked lists)
    - The default structure for file systems, graphical user interfaces, databases, websites, and other computer systems

## 8.1.1 Tree Definitions and Properties
A `tree` is an ADT that stores elts hierarchically.
- With the exception of the top elt (aka `root`)
    - Every elt in a tree has a `parent` elt and zero or more `children` elts

**Formal Tree Definition**:
- Define a **tree** `t` as a set of **nodes** storing elts such that the nodes have a **parent-child** relationship that satisfies the following properties:
    1. If `T` is nonempty, it has a special node, called the **root** of `T`, that has no parent.
    2. Each node `v` of `T` different from the root has a unique **parent** node `w`; every node with parent `w` is a **child** of `w`
- According to the definiton, a tree **CAN** be empty--having no nodes.
    - This allows us to define a tree recursively s.t. a tree `T` is either empty or consists of a node `r` called the root of `T` and a (possibly empty) set of subtrees whose roots are the children of `r`

**Other Node Relationships**:
- Two nodes that are children of the same parent are **siblings**. A node `v` is **external** (aka a **leaf** node) if `v` has no children and **internal** if it does.
    - A node `u` is an **ancestor** of a node `v` if `u = v` or `u` is an ancestor of the parent of `v`. Conversely, the opposite relationship is the **descendent**.
    - The **subtree** of `T` *rooted** at a node `v` is the tree consisiting of all the descendants of `v` in `T` (including `v` itself)

**Edges and Paths in Trees**:
- An **edge** of tree `T` is a pair of nodes `(u, v)` s.t. `u` is the parent of `v` or vice versa. A **path** of `T` is a sequence of nodes such that any two consecutive nodes in the sequence form an edge.

**Inheritance hierarchy for modeling various abstractions and implementations of `tree`**:
```text
                            Tree
                            |
                            v
                BinaryTree, LinkedTree
                    |
                    v
    ArrayBinaryTree, LinkedBinaryTree
```

**Ordered Trees**:
- A tree is **ordered** if there is a meaningful linear order among the children of each node; that is, we purposefully identify the children of a node as being the first, second, third, and so on.
    - Such an order is visualized by arranging siblings left to right, according to their order.

## 8.1.2 The Tree Abstract Data Type
Define a tree ADT using the concept of a **position** as an abstraction for a node of a tree. An elt is stored at each position, and positions satisfy parent-child relationships that define the tree structure. A position object for a tree supports the method:
- `p.element()`: Return the elt stored at position `p`

The tree ADT then supports the following **accessor methods**, allowing a user to navigate the various positions of a tree:
1. `T.root()`: Return the position of the root of tree `T` or None if empty
2. `T.is_root(p)`: Return True if position `p` is the root of tree `T`
3. `T.parent(p)`: Return the position of the parent of position `p`, or None if `p` is the root of `T`
4. `T.num_children(p)`: Return the number of children of position `p`
5. `T.children(p)`: Generate an iteration of the children of position `p`
6. `T.is_leaf(p)`: Return True if position `p` does not have any children
7. `len(T)`: Return the number of positions (and hence elts) that are contained in tree `T`
8. `T.is_empty()`: Return True if tree T does not contain any positions
9. `T.positions()`: Generate an iteration of all positions of tree T
10. `iter(T)`: Generate an iteration of all elts stored within tree T
    - The methods that accept a position as an arg generates a `ValueError` if position is invalid for T

**A Tree Abstract Base Class in Python**:
```python
class Tree:
    """Abstract base class representing a tree structure"""

    #----- nested Position class -----
    class Position:
        """An abstraction representing the location of a single elt"""

        def element(self):
            """Return the elt stored at this Position"""
            raise NotImplementedError("Must be implemented by subclass")
        
        def __eq__(self, other):
            """Return True if other Position represents the same location"""
            raise NotImplementedError("Must be implmented by subclass")
        
        def __ne__(self, other):
            """Return True if other Position represents the same location"""
            return not (self == other)
    
    #----- abstract methods that concrete subclasses must support -----
    def root(self):
        """Return Position representing the tree's root (or None if empty)"""
        raise NotImplementedError("Must be implmented by subclass")
    
    def parent(self, p):
        """Return Position representing p's parent (or None if p is root)"""
        raise NotImplementedError("Must be implmented by subclass")
    
    def num_children(self, p):
        """Return the number of children that Position p has"""
        raise NotImplementedError("Must be implmented by subclass")
    
    def children(self, p):
        """Generate an iteration of Positions representing p's children"""
        raise NotImplementedError("Must be implmented by subclass")

    def __len__(self):
        """Return the total number of elts in the tree"""
        raise NotImplementedError("Must be implmented by subclass")
    
    #----- concrete methods implemented in this class -----
    def is_root(self, p):
        """Return True if Position p represents the root of the tree"""
        return self.root() == p
    
    def is_leaf(self, p):
        """Return True if Position p does not have any children"""
        return self.num_children(p) == 0
    
    def is_empty(self):
        """Return True if the tree is empty"""
        return len(self) == 0
```

## 8.1.3 Computing Depth and Height
**Depth**:

Let `p` be the position of a node of a tree T. The **depth** of p is the number of ancestors of p, excluding p itself.
- The depth of `p` can be recursively defined as follows:
    - If `p` is the root, then the depth of `p` is 0
    - Otherwise, the depth of `p` is one plus the depth of the parent of `p`

**Recursive algorithm for finding depth--O(n)**
```python
def depth(self, p):
    """Return the number of levels separating Position p from the root"""
    if self.is_root(p):
        return 0
    else:
        return 1 + self.depth(self.parent(p))
```

**Height**:

The **height** of a position `p` in a tree `T` is also defined recursively:
- If `p` is a leaf, then the height is 0
- Otherwise, the height of p is one more than the maximum of the heights of `p`'s children

```python
def _height1(self):
    """Return the height of the tree"""
    # Worst-case O(n^2) time
    return max(self.depth(p) for p in self.positions() if self.is_leaf(p))

def _height2(self, p):
    """Return the height of the subtree rooted at Position p"""
    if self.is_leaf(p):
        return 0
    else:
        return 1 + max(self._height2(c) for c in self.children(p))

# Wrap the non-public _height2 with a public height() method
def height(self, p=None):
    """Return the height of the subtree rooted at Position p

    If p is None, return the height of the entire tree
    """
    if p is None:
        p = self.root()
    
    return self._height2(p)
```
