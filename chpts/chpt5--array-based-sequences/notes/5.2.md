# 5.2 Low-Level Arrays
- 8 bits in a byte
- A computer system has a huge number of bytes of memory -> and a **memory address** is used to track what information is stored in what byte
    - Despite the sequential nature of the numbering system, computer hardware is designed, in theory, so that any byte of the main memory can be efficiently accessed based upon its memory address
    - A computer's main memory performs as **random access memory (RAM)** -> it is as easy to access `byte #81281` as `byte #1`
        - We say that storing and retrieving data takes $O(1)$ time
- A group of related variables can be stored one after another in a contiguous portion of the computer's memory -> such a representation is noted as an **array**
    - i.e. a text string is stored as an ordered sequence of individual characters
        - each character is represented using the Univode character set--Python internally represents each Unicode character with 16 bits (2 bytes)
    - so a string `example` is stored in 14 bytes of consecutive memory -> 2 bytes ea char -> an array of 6 characters
        - an index is derived by `start + (cellsize * idx)`

## 5.2.1 Referential Arrays
- **LISTS** and **TUPLES** are **referential** structures
    - i.e. array `['Rene', 'Joseph', 'Janet', 'Jonas']` is stored as a referential array with each index as a reference to the string stored elsewhere since each index of a list must be the same size, otherwise if allocating enough space in each index to contain the largest string, there ends up being wasted space
- A single list instance may include multiple references to the same object as elements of the list
- It is possible for a single object to be an element of two or more lists
    - i.e. when making a slice of a list, both the sliced list and og list refer to the same elts
- When the elts of the list are immutable objects--integer instances--neither of the lists can cause a change to the shared object -> making a change to one list, it just makes the `list[idx]` point to the newly assigned integer
    - If the contents of a list are mutable, then it is necessary to create a **deep copy** so that updating the new list does not affect the og
- Init an array of ints using a syntax done via: `arr = [0] * 5`--this creates `[0, 0, 0, 0, 0]`
    - all cells refer to the same object--`0`
        - however this is okay because `0` is immutable so when making an update--`arr[1] = 2`, now idx one of `arr` refers to a new int `2`
- `extend` used to add all elts from one list to the end of antoehr list
    - the extended list does not receive copies of those elts but rather references to those elts -> so now the extended indices refer to whatever the `.extend(array2)` input arr referred to

## 5.2.2 Compact Arrays in Python
- Strings are represented using an array of characters (not an array of references)--called a **compact array** because the array is storing the bits that represent the primary data (characters in this case)
    - Compact arrays have seveal advantages over referential structures in terms of computing performance -> the overall memory usage is lower for a acompact structure because there is no overhead devoted to the explicit storage of the sequence of memory references
        - A referential structure typically uses 64-bits for memory address stored in the array
- The `getsizeof` function of the `sys` module can be used to query the number of bytes being used for the primary storage of any object--i.e. `getsizeof()` on an array of ints will not count the memory used for the int objects pointed to by the memory addresses and only all of the memory addresses
    - To create compact arrays:
        - Use the `array` class
        - i.e. `primes = arrays('i', [2, 3, 4, 5, 6])`--'i' is a type code signifying ints

`Array` module type codes:
```
Code    C Data Type         Typical num of bytes
'b'     signed char         1
'B'     unsigned char       1
'u'     Unicode char        2 or 4
'h'     signed short int    2
'H'     unsigned short int  2
'i'     signed int          2 or 4
'I'     unsigned int        2 or 4
'l'     signed long int     4
'L'     unsigned long int   4
'f'     float               4
'd'     float               8
```
- Important:
    - The `array` module does not support user-defined data types!
        - Compact arrays of such structures can be created with the lower-level support of a module named `ctypes`
