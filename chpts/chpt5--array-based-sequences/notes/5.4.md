# 5.4 Efficiency of Python's Sequence Types
- Examining the performance of all Python's sequence types

## 5.4.1 Python's `List` and `Tuple` Classes
- The **nonmutating** behaviours of the `list` class are precisely those that are supported by the `tuple` class
    - `tuples` are typically more memory efficient than `lists` because they are **immutable**
    - Therefore, there is no need for an underlying dynamic array with surplus capacity
    - Asymptotic effciency of the nonmutating behaviours of the `list` and `tuple` classes:
    ```
    Operation           Running Time
    --------------------------------
    len(data)           O(1)
    data[j]             O(1)
    data.count(value)   O(n)
    data.index(value)   O(k + 1)
    value in data       O(k + 1)
    data1 == data2      O(k + 1)
    data[j:k]           O(k - j + 1)
    data1 + data2       O(n_1 + n_2)
    c * data            O(cn)
    ```
    - **Constant-Time Operations**:
        - The length of an instance is returned in constant time because an instance explicitly maintains such state information!
    - **Searching for Occurrences of a Value**:
        - Each of the `count`, `index`, and `__contains__` methods proceed through iteratin of the sequence from the left to right -> $O(n)$
    - **Lexicographic Comparisons**:
        - Comparisons between two sequences are defined lexicographically. In the worst case, needs to examine every elt of the shorter sequence!
    - **Creating New Instances**:
        - The running time is dependent on the construction and initialization of the new result so it is proportional to the length of the result
    - **Mutating Behvaiours**:
        - i.e. `data[j] = val` -> $O(1)$ runtime
        ```
        Operation               Running Time
        ------------------------------------
        data[j] = val           O(1)*
        data.append(val)        O(1)*
        data.insert(k, val)     O(n - k + 1)*
        data.pop()              O(1)*
        data.pop(k)             O(n - k)*
        data.remove(val)        O(n)*
        data.extend(data2)      O(n_2)*
        data.reverse()          O(n)
        data.sort()             O(nlogn)

        * -> amortized
        ```

## 5.4.2 Python's String Class
- Analysis on operation runtimes related to strings class
    - **Pattern Matching**:
        - Runs in worst case $O(nm)$ since we condier the $n - m + 1$ possible starting indices for the patterns and we spend O(m) time at each starting position checking of the pattern mathes
    - **Composing Strings**:
        - Efficient strategy is to build out string in `list` then converting `list` to `string` since doing `string += char` is $O(n)$ time since strings are immutable!
        ```Python
        tmp = []

        for c in document:
            if c.isalpha():
                tmp.append(c)
        
        letters = "".join(tmp)
        return letters
        ```
        - This can also be written in a one liner via `letters = "".join([c for c in document if c.isalpha()])`
