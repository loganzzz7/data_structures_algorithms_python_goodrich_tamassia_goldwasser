# 7.7 Link-Based vs Array-based Sequences
Summary of pros and cons of array-based and link-based data structures that have been introduced thus far
- **Advantages of Array-Based Sequences**:
    1. $O(1)$-time access to an elt based on an integer index. Has the ability to access the $k^{th}$ elt in $O(1)$ time whereas in a link-based sequence, accessing the $k^{th}$ elt requires traversal from start to $k$
    2. Operations with equivalent asymptotic bounds typically run a constant factor more efficiently with an array-based structure vs a linked structure.
        - i.e. `enqueue` operation for a queue--ignoring the resizing, this operation for the `ArrayQueue` class involves an arithmetic calc of the new index, an inc of an int, and storing a ref to the elt in the array
        - The same process for `LinkedQueue` requires an init of a node, linking of the nodes, and inc to int.
            - The `LinkedQueue` version results in more CPU operations even though both are technically $O(1)$ time--especially due to the init of the new node
    3. Array-based representations use proportionally less memory than linked structures.
        - For link-based structures, there exists a need for more references as each node needs to point to next.
- **Advantages of Link-Based Sequences**:
    1. Link-based structures provide worst-case time bounds for their operations.
        - This contrasts the amortized bounds associated with the expansion or contraction of a dynamic array
    2. Link-based structures support $O(1)$-time insertions and deletions at arbitrary positions.
        - The ability to perform a constant-time insertion or deletion with the `PositionalList` class by using a `Position` to describe the location of the operation is the most significant advantage of the linked list.
            - In contrast, when inserting / deleting from an array-based sequence, the rest of the sequence requires to be shifted, therefore this takes $O(n - k + 1)$ time--performed at idx $k$
