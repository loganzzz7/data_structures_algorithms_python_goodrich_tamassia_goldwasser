# 7.3 Doubly Linked Lists
- In a singly linked list: each node maintains a refernce to the node that is immediately after it -> useful when pmanaging a sequence of elts
    - However, there are limitations that stem from the asymmetry of a singly linked list -> unable to efficiently delete a node at the tail of the list.
        - Cannot efficiently delete an arbitrary node from an interior position of the list if only given a reference to that node because we cannot determine the node that immediately precedes the node to be deleted and in order to delete the node, the previous need to point to the next
    - SO in a **doubly-linked list**, there exists **both** `prev` and `next` ptrs

**Header and tail Sentinels**
- In **doubly-linked lists** -> $\exists$ header and tail sentinels (a `header` node at the beginning of the list and a `tail` node at the end).
    - These "dummy" nodes are `sentinels` and they do not sore elts of the primary sequence
    - When using sentinels, an empty list is init so that the `next` field of the `header` points to the `tail` and the `prev` field of the `tail` points to the `header`
    - **Advantages of using sentinels**:
        - Although it is possible to implement a **doubly-linked list** w out sentinels, they simplify the logic of the operations
            - Most notably, the `header` and `tail` nodes **NEVER** change!
        - **Inserting and Deleting with a Doubly Linked List**
            - Every insertion and deletion will be between a pair of existing nodes (empty case: dummy nodes!)
                - So when a new elt is inserted at the front, add new node between header and the node that is currently after the header!
                - Same logic with deletion, just point prev to prev of del and for prev of del point next to next of del

## 7.3.1 Basic Implementation of a Doubly Linked List
- Preliminary implementation of a doubly linked list: `_DoublyLinkedBase`
    - Named with a leading underscore because don't need it to provide a public interface for general use
        - Linked lists can support general insertions and deletions in $O(1)$ worst-case time, **ONLY IF** the location of an operation can be succinctly identified
        - Unlike array-based sequences, an integer idx is not useful as there is no efficient way to find the `j-th` elt -> this would still require a traversal of the list
    - The most direct way to describe the location of an operation is by identifying a relevant node of the list. **HOWEVER**, want to encapsulate the inner workings of our data structure to avoid having users directly access nodes of a list.
        - Therefore, will later describe two public classes that inherit from the `_DoublyLinkedBase` class to provide more coherent abstractions.

**Node Implementation for Doubly-linked List**:
```python
class _Node:
    """Lightweight, non public class for storing a doubly linked list"""
    __slots__ = "_element", "_prev", "_next"

    def __init__(self, element, nxt, prev):
        self._element = element
        self._prev = prev
        self._next = nxt
```

**`_DoublyLinkedBase` Implementation**:
```python
class _DoublyLinkedBase:
    """A base class providing a doubly linked list representation"""
    
    class _Node:
        """Lightweight, nonpublic class for storing a doubly linked node"""
        
        __slots__ = "_element", "_prev", "_next"

        def __init__(self, elt, prev, nxt):
            self._element = elt
            self._prev = prev
            self._next = nxt
    
    def __init__(self):
        """Create an empty list"""
        self._header = self._Node(None, None, None)
        self._trailer = self._Node(None, None, None)
        self._header._next = self._trailer
        self._trailer._prev = self._header
        self._size = 0
    
    def __len__(self):
        """Return the num of elts in the list"""
        return self._size
    
    def is_empty(self):
        return True if self._size == 0 else False
    
    def _insert_between(self, e, predecessor, successor):
        """Add elt e between two existing nodes and return new node"""
        newest = self._Node(e, predecessor, successor)
        predecessor._next = newest
        successor._prev = newnest
        self._size += 1
        return newest
    
    def _delete_node(self, node):
        """Delete non sentinel node from the list and return its element"""
        predecessor = node._prev
        successor = node._next
        predecessor._next = successor
        successor._prev = predecessor
        self._size -= 1
        element = node._element
        # deprecate node related attributes!
        node._prev = node._next = node._element = None
        return element
```

## 7.3.2 Implementing a Deque with a Doubly Linked List
- The `deque` ADT achieves all operations in **amortized** $O(1)$ time due to occasional need to resize the array
    - With an implementation based on a `DoublyLinkedList`, all `deque` operations can be achieved in **worse-case** $O(1)$ time

**`LinkedDeque` Implementation**
```python
class LinkedDeque(_DoublyLinkedBase):
    def first(self):
        if self.is_empty():
            raise Empty("Deque is empty")
        return self._header._next._element

    def last(self):
        if self.is_empty():
            raise Empty("Deque is empty")
        return self._trailer._prev._element
    
    def insert_first(self, e):
        self._insert_between(e, self._header, self._header._next)
    
    def insert_last(self, e):
        self._insert_between(e, self._trailer._prev, self._trailer)
    
    def delete_first(self):
        """Remove and return the elt from the front of the deque
        
        exception on empty"""
        if self.is_empty():
            raise Empty("Deque is empty")
        return self._delete_node(self._header._next)
    
    def delete_last(self):
        if self.is_empty():
            raise Empty("Deque is empty")
        return self._delete_node(self._trailer._prev)
```
