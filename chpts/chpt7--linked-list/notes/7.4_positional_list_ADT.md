# 7.4 The Positional List ADT
- The abstract data types that we've looked at so far (stacks, queues, double-ended queues) only allow update operations that occur at one end of a sequence or the other -> want to have a more general abstraction
    - **Want to design**: an abstract data type that provides a user a way to refer to elts anywhere in a sequence and to perform arbitrary insertions and deletions
        - When working with array-based sequences (i.e. Python `list`), integer indices is the means for describing the location of an elt or the location at which an insertion or deletion should take place
            - **HOWEVER** numeric indices != a good choice for describing positions within a linked list because we cannot efficiently access an entry knowing only its index -> finding an index requires traversal from the start -> not $O(1)$ time!!
            - **SO** goal == identifying the position of an elt in a sequence without the use of an int index!
    - **Idea**: a node reference as a position:
        - One of the benefits of a linked list is that it is possible to perform $O(1)$-time insertions and deletions at arbitrary positions of the list, as long as we are given a reference to a relevant node of the list
            - **THEREFORE**, it is tempting to develop an ADT in which a node reference serves as the mechanism for describing a position
                - i.e. In `_DoublyLinkedBase` $\exists$ methods `_insert_between` and `_delete_node` that accept node references as params!
        - **HOWEVER**, such direct use of nodes would violate the oop principles of abstraction and encapsulation!
            - Reasons to encapsulate the nodes of a linked list:
                1. Simpler for users of our data structure if they are not bothered with unnecessary details of our implementation, such as low-level manipulation of nodes or our reliance on the use of sentinel nodes
                2. Provide a more robust data structure if we do not permit users to directly access or manipulate the nodes -> ensure that users cannot invalidate the consistency of a list by mismanaging the linking of nodes!
    - **FINALIZED APPROACH**:
        - Introduce an independent `position` abstraction to denote the location of an element within a list and then a complete `positional list ADT` that can encapsulate a doubly linked list (or even an array-based sequence)

## 7.4.1 The Positional List Abstract Data Type
Defining a `positional list ADT` and the `position` abstract data type to describe a location within a list.
- A position instance is a simple object, supporting **ONLY** the following method:
    1. `p.element()`: return the element stored at position `P`

- In the context of the positional list ADT, positions serve as parameters to come methods and as return values from other methods. In describing the behaviours of a positional list, begin by presenting the accessor methods supported by a list `L`:
    1. `L.first()`: Return the position of the first element of `L` or `None` if `L` is empty
    2. `L.last()`: Return the position of the last elt of `L` or `None` if `L` is empty
    3. `L.before(p)`: Return the position of `L` immediately before the position `p` or `None` if `p` is the first position
    4. `L.after(p)`: Return the position of `L` immediately after the position `p` or `None` if `p` is the last position
    5. `L.is_empty()`: Return True if `L` does not contain any elements
    6. `len(L)`: Return the number of elts in the list
    7. `iter(L)`: Return a forward iterator for the elts of the list
    8. `L.add_first(e)`: Insert a new elt e at the front of `L`, returning the position of the new elt
    9. `L.add_last(e)`: Insert a new elt e at the back of `L`, returning the position of the new elt
    10. `L.add_before(p, e)`: Insert a new element `e` just before position `p` in `L`, returning the position of the new element
    11. `L.add_after(p, e)`: Insert a new element `e` just after position `p` in `L`, returning the position of the new elt
    12. `L.replace(p, e)`: Replace the elt at position `p` with the elt `e`, returning the elt formerly at position `p`
    13. `L.delete(p)`: Remove and return the elt at position `p` in `L`, invalidating the position

## 7.4.2 Doubly Linked List Implementation
A complete implementation of a `PositionalList` class using a doubly linked list that satisifies the following:
- **Proposition 7.2**: Each method of the positional list ADT runs in worst-case $O(1)$ time when implemented with a doubly linked list

```python
class PositionalList(_DoublyLinkedBase):
    """A sequential container of elements allowing positional access"""

    # ----------Nested Position Class----------
    class Position:
        """An abstraction representing the location of a single element"""
        def __init__(self, container, node):
            """Constructor should not be invoked by user"""
            self._container = container
            self._node = node
        
        def element(self):
            """Return the element stored at the position"""
            return self._node._element
        
        def __eq__(self, other):
            """Special func returning True if other is a Position representing the same location"""
            return type(other) is type(self) and other._node is self._node
        
        def __ne__(self, other):
            """Return True if other does not represent the same location"""
            return not (self == other)
    
    # Utility methods
    def _validate(self, p):
        """Return position's node, or raise appropriate error if invalid"""
        if not isinstance(p, self.Position):
            raise TypeError("p must be proper Position type")
        
        if p._container is not self:
            raise ValueError("p does not belong to this container")
        
        if p._node._next is None:
            # checking for deprecation
            raise ValueError("p is no longer valid")
    
    def _make_position(self, node):
        """Return Position instance for given node (or None if sentinel)"""
        if node is self._header or node is self._trailer:
            # boundary violation
            return None
        else:
            # return the position instance
            return self.Position(self, node)
    
    # Accessor methods
    def first(self):
        return self._make_position(self._header._next)

    def last(self):
        return self._make_position(self._trailer._prev)
    
    def before(self, p):
        """Return the Position just before Position p (or None if p is first)"""
        node = self._validate(p)
        return self._make_position(node._prev)

    def after(self, p):
        """Return the Position just after Position p (or None if last)"""
        node = self._validate(p)
        return self._make_position(node._next)

    def __iter__(self):
        """Generate a forward iteration of the elts of the list"""
        curser = self.first()
        
        while cursor is not None:
            yield cursor.element()
            curser = self.after(cursor)
    
    # Mutators
    # Override inherited version to return Postion, rather than Node

    def _insert_between(self, e, pre, succ):
        node = super()._insert_between(e, pre, succ)
        return self._make_position(node)
    
    def add_first(self, e):
        return self._insert_between(e, self._header, self._header._next)
    
    def add_last(self, e):
        return self._insert_between(e, self._trailer._prev, self._trailer)
    
    def add_before(self, p, e):
        original = self._validate(p)
        return self._insert_between(e, original._prev, original)
    
    def add_after(self, p, e):
        original = self._validate(p)
        return self._insert_between(e, original, original._next)
    
    def delete(self, p):
        original = self._validate(p)
        return self._delete_node(original)
    
    def replace(self, p, e):
        original = self._validate(p)
        old_value = original._element
        original._element = e
        return old_value
```
